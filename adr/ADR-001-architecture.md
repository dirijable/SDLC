# ADR-001: Серверное веб-приложение Spring Boot с PostgreSQL

## Контекст и постановка задачи

SRS задаёт Java 21, Spring Boot, PostgreSQL, один барбер-шоп и настольные браузеры (REQ-INT-003, REQ-INT-004). Нужно выбрать структуру приложения, достаточную для каталога, бронирования и панели без лишней инфраструктуры.

## Драйверы решения

- Одна команда и ограниченный срок проекта.
- Атомарность бронирования REQ-FUNC-007.
- 50 одновременных пользователей и 2 секунды для 95% запросов REQ-PERF-001..002.
- Простое развёртывание и сопровождение.

## Рассмотренные варианты

1. Серверный модульный монолит Spring Boot с HTML-страницами и PostgreSQL.
2. Отдельные SPA-клиент и REST-сервер.
3. Микросервисы каталога, записей и расписания.

## Итог решения

Выбран вариант 1. Контроллеры, сервисы и репозитории разделены логически, но собираются в один JAR. Он соответствует ограничениям SRS и позволяет выполнять изменение слота в одной транзакции БД. Для интерфейса используются серверные страницы и минимальный JavaScript для фильтров и выбора слота.

### Последствия

- Проще выпуск и интеграционное тестирование одной инсталляции.
- UI и сервер релизятся вместе; независимый выпуск клиента не предусмотрен.
- При росте нагрузки потребуется повторно оценить структуру, но в заданном масштабе это не требуется.

### Подтверждение

В репозитории должны быть контроллеры, сервисы и слой доступа к данным без прямого SQL из представлений. Сборка `gradle bootJar` создаёт один JAR; интеграционный тест работает с PostgreSQL.

## Плюсы и минусы вариантов

| Вариант | Плюсы | Минусы |
|---|---|---|
| Модульный монолит | Один выпуск, одна транзакционная граница, меньше инфраструктуры | Связанный выпуск UI и сервера |
| SPA + REST | Независимый интерфейс, гибкий клиент | Дополнительная сборка, API-контракт и тестирование |
| Микросервисы | Независимые релизы модулей | Сложные транзакции и развёртывание без пользы для одного салона |
