Давайте очень медленно и на пальцах, с конкретными строчками кода как доказательством.

## Что вообще делает Controller?

У `Controller` есть **ровно две задачи**, и больше он не делает ничего:

**Задача 1: "Услышать" клик по кнопке**

```java
this.mainFrame.getEnterDataButton().addActionListener(e -> openInputDialog());
```

Это как будто контроллер говорит кнопке: "Если тебя нажмут - позови меня, я открою окно ввода". Больше он с `mainFrame` не общается вообще нигде в коде - только вешает этот один обработчик, один раз, при создании.

**Задача 2: "Передать" данные из диалога в модель**

Когда пользователь заполнил диалог и нажал "ОК", данные приходят в `Controller` вот сюда:

```java
private void updateModel(BloodPressureInput data) {
    model.updateData(
            data.birthDate(),
            data.weightKg(),
            data.systolic(),
            data.diastolic());
}
```

Смотрите буквально: `data` - это то, что ввёл пользователь (дата, вес, давление). Контроллер **ничего не проверяет сам**, не считает ничего сам - он просто берёт эти 4 значения и **передаёт их в модель**, вызывая `model.updateData(...)`.

**Вот и всё, что делает Controller.** Он - просто "посредник" или "передатчик": ловит клик кнопки → открывает окно → берёт то, что ввёл пользователь → отдаёт это модели. Он не хранит результат, не считает давление, не обновляет экран - ничего из этого.

---

## Что значит "модель отвечает за работу с данными"?

Да, именно так. Модель (`BloodPressureModel`) делает **всю содержательную работу**:

1. **Проверяет**, корректны ли данные (метод `validate`).
2. **Хранит** их у себя (поля `birthDate`, `weightKg`, `systolic`, `diastolic`).
3. **Считает** результат - идеальное давление и оценку (метод `recalculate`).
4. **Хранит результат** тоже у себя (поля `idealSystolic`, `idealDiastolic`, `estimation`).
5. **Оповещает всех**, кто хочет знать, что она изменилась (`firePropertyChange`).

Модель не "отдаёт кому-то что-то" в смысле "вызывает чужой метод и что-то ему передаёт руками". Она делает наоборот: **рассылает сигнал** "эй, я изменилась!" всем, кто заранее подписался - а дальше уже дело подписчика (в нашем случае `MainFrame`), что с этим сигналом делать. Модель вообще не знает, кто на неё подписан и что они будут делать с этим уведомлением.

---

## "Что значит обновляет модель, где мы это видим?"

Вот смотрите **пошагово, что физически происходит в памяти компьютера**, когда вы жмёте "ОК" в диалоге:

**Шаг А.** До нажатия ОК, в модели (объект `model`, который живёт с самого запуска программы) поля выглядят, допустим, так (первый раз - пустые/дефолтные):
```
model.birthDate = null
model.weightKg = 0.0
model.systolic = 0
model.diastolic = 0
model.hasData = false
```

**Шаг Б.** Вы вводите в диалоге: 01.01.1990, вес 70, давление 120/80, жмёте ОК.

**Шаг В.** Внутри `InputDialog` собирается объект:
```java
new BloodPressureInput(LocalDate.of(1990,1,1), 70.0, 120, 80)
```
Это **новый, отдельный, временный** объект - просто "посылка" с четырьмя значениями внутри. Он ещё нигде не "сохранён" по-настоящему, это просто данные, которые едут дальше.

**Шаг Г.** Эта "посылка" (`data`) попадает в `Controller.updateModel(data)`:
```java
private void updateModel(BloodPressureInput data) {
    model.updateData(
            data.birthDate(),     // достаём дату из посылки -> 1990-01-01
            data.weightKg(),      // -> 70.0
            data.systolic(),      // -> 120
            data.diastolic());    // -> 80
}
```
Контроллер здесь **распаковывает посылку** и зовёт метод **того самого** `model` (это тот же объект, что был создан в `Main` в самом начале - `Controller` хранит на него ссылку в своём поле).

**Шаг Д.** Вот теперь мы **внутри модели**, в методе `updateData`:
```java
public void updateData(LocalDate birthDate, double weightKg, int systolic, int diastolic) {
    validate(birthDate, weightKg, systolic, diastolic);  // проверка - ошибок нет, идём дальше

    this.birthDate = birthDate;     // ⬅ ВОТ ЗДЕСЬ. model.birthDate меняется с null на 1990-01-01
    this.weightKg = weightKg;       // ⬅ model.weightKg меняется с 0.0 на 70.0
    this.systolic = systolic;       // ⬅ model.systolic меняется с 0 на 120
    this.diastolic = diastolic;     // ⬅ model.diastolic меняется с 0 на 80
    this.hasData = true;            // ⬅ теперь true

    recalculate();  // считает idealSystolic, idealDiastolic, estimation и тоже сохраняет их в полях модели

    support.firePropertyChange(PROP_DATA_CHANGED, null, this);  // рассылка уведомления
}
```

**Вот эти 5 строчек с `this.` - это и есть "модель обновилась".** До этого момента поля объекта `model` содержали старые (или пустые) значения, после выполнения этих строк - они содержат новые. Объект `model` **тот же самый** (не создаётся заново!), просто его внутренние поля перезаписались.

**Шаг Е.** После этого модель считает результат (`recalculate()`) и **тоже записывает его в свои поля** (`idealSystolic`, `idealDiastolic`, `estimation`) - точно так же через `this.idealSystolic = ...` внутри `recalculate`.

**Шаг Ж.** `firePropertyChange(...)` - модель говорит "готово, я обновилась" всем подписчикам. Единственный подписчик - `mainFrame`, у него срабатывает `onModelChanged`, он читает **те самые** поля из **того самого** объекта `model` (через геттеры `getIdealSystolic()` и т.д.) и показывает их на экране.

---

## Ключевая мысль, которую нужно понять

**Есть только ОДИН объект модели** (`model`), созданный один раз в `Main`. Все классы (`MainFrame`, `Controller`) держат **ссылку** на этот же самый объект (как несколько человек, у которых записан один и тот же номер телефона одного и того же человека - все звонят одному и тому же человеку, а не разным копиям).

- Когда `Controller` вызывает `model.updateData(...)` - он **меняет поля именно этого объекта**.
- Когда `MainFrame` в `onModelChanged` вызывает `model.getIdealSystolic()` - он **читает поля из этого же самого объекта**, который только что поменял `Controller`.

Поэтому никакой явной "передачи" данных от `Controller` к `MainFrame` в коде нет - они **оба** просто общаются с одним и тем же объектом `model`: один - **записывает** в него данные, другой - **читает** из него данные, а модель через уведомление лишь "будит" второго, когда первый закончил запись.

Стало понятнее? Если что-то конкретное всё ещё непонятно (например, "что такое ссылка на объект" или конкретный момент в этой цепочке) - зацепитесь за него, разберём отдельно.

## Аналогия

Представьте: **Controller** - это вы. Вы хотите узнать, что человек напишет в анкете, но сами анкету не заполняете и не стоите над душой у человека, пока он пишет.

Вы делаете так: даёте человеку (это **InputDialog**) **свой номер телефона** и говорите: "Заполни анкету, а когда закончишь - позвони мне по этому номеру и продиктуй, что написал".

Человек заполняет анкету, потом **звонит вам сам** (не вы ему, а он вам!) и диктует данные. Вот в этот момент, когда он вам звонит - вы и "получаете данные". Не раньше.

## То же самое в коде

**Момент 1: Controller даёт свой "номер телефона"**

```java
private void openInputDialog() {
    InputDialog dialog = new InputDialog(mainFrame, model.getLastInput(), this::updateModel);
    //                                                                     ^^^^^^^^^^^^^^^^^
    //                                                                     вот это - "номер телефона"
    dialog.setVisible(true);
}
```

`this::updateModel` - это буквально **ссылка на метод** `updateModel`, который принадлежит **этому конкретному** объекту `Controller` (`this`). Это не вызов метода прямо сейчас! Это просто "вот тебе бумажка с номером - позвонишь, когда будет результат". Эта "бумажка" передаётся в конструктор `InputDialog` третьим параметром.

**Момент 2: InputDialog сохраняет этот "номер" у себя**

Внутри `InputDialog`, в конструкторе, третий параметр называется `onSubmit`:

```java
public InputDialog(JFrame owner, BloodPressureInput initialData, Consumer<BloodPressureInput> onSubmit) {
    ...
    configureListeners(okButton, cancelButton, onSubmit);
    ...
}
```

`onSubmit` - это и есть переданный "номер телефона" (`this::updateModel`), просто теперь у него **новое локальное имя** внутри `InputDialog` - `onSubmit`. Дальше он передаётся ещё дальше, в `configureListeners`:

```java
private void configureListeners(JButton okButton, JButton cancelButton, Consumer<BloodPressureInput> onSubmit) {
    ...
    okButton.addActionListener(e -> submitData(onSubmit));
}
```

Тут "номер" вешается на кнопку ОК - как будто к кнопке привязали бумажку с номером телефона.

**Момент 3: пользователь нажимает ОК - вот тут и происходит "звонок"**

```java
private void submitData(Consumer<BloodPressureInput> onSubmit) {
    try {
        onSubmit.accept(readInputData());
        //^^^^^^^^^^^^^ ВОТ ОН, "ЗВОНОК"
```

`onSubmit.accept(readInputData())` - это то самое место в коде, где `InputDialog` **сам, по своей инициативе**, вызывает тот метод, на который ему дали ссылку. А что такое `onSubmit`? Это `this::updateModel` из Controller, помните? Значит, строчка `onSubmit.accept(readInputData())` **по факту равнозначна** вот этому вызову:

```java
controller.updateModel(readInputData());
```

Просто написана она **не в самом Controller**, а внутри InputDialog - потому что именно InputDialog в этот момент знает, что пользователь нажал ОК и данные готовы.

**Момент 4: Controller "получает данные" - вот он, ответ на ваш вопрос**

```java
private void updateModel(BloodPressureInput data) {
    model.updateData(data.birthDate(), data.weightKg(), data.systolic(), data.diastolic());
}
```

Вот **этот самый метод** и есть тот момент, когда Controller "получает данные". Параметр `data` - это и есть то, что вам "продиктовали по телефону". Он получает их **не потому, что кто-то извне что-то ему прислал сам по себе**, а потому что **сам же дал ссылку на этот метод** InputDialog'у заранее, а тот её вызвал в нужный момент.

---

## Итог - от кого и когда

**От кого:** формально метод `updateModel` вызывает объект `InputDialog` (та самая строчка `onSubmit.accept(...)` внутри него).

**Когда:** в момент, когда пользователь нажал кнопку "ОК" в диалоговом окне, и `readInputData()` успешно собрал данные без ошибок парсинга.

**Почему это вообще возможно:** потому что ещё **раньше**, при **создании** диалога (`openInputDialog()`), Controller сам передал диалогу "ссылку на самого себя" (`this::updateModel`) - как будто заранее оставил номер телефона. Без этого шага InputDialog вообще не знал бы, куда "звонить" с результатом.

## Как связаны классы - если коротко

- **Controller** знает про **MainFrame** (держит ссылку) и про **BloodPressureModel** (держит ссылку) - создаются они в `Main` и передаются в конструктор Controller.
- **Controller** создаёт **InputDialog** сам, каждый раз заново, при каждом клике по кнопке - и в момент создания даёт диалогу ссылку на свой метод.
- **InputDialog** не хранит долговременную ссылку на Controller как на класс - он просто держит одну единственную "функцию для звонка" (`onSubmit`), не зная и не заботясь о том, что это конкретно `Controller.updateModel`.
- **MainFrame** знает про **BloodPressureModel** (только чтобы подписаться на неё в конструкторе) - и всё, больше никак с ней не взаимодействует.
